# 기획 요약과 우선순위

원본 기획서: "(가제) 출근! 조달청 신입 — 게임 기획서" (Claude 문서). 이 파일은 작업용 요약이다.
상태 칸은 작업하면서 갱신한다: `뼈대`(코드 있음, Godot 미검증) / `완료`(실행 확인) / `-`(미착수).
11/17 기준 `완료`는 Godot 4.5.2 헤드리스 스모크 테스트(`tests/smoke_loop.gd`)와 웹 빌드(헤드리스 크롬)로 확인한 것이다.
직접 플레이 확인은 `docs/playtest-checklist.md`.

## 우선순위 규칙

| 등급 | 정의 | 완료 목표 |
| --- | --- | --- |
| P0 필수 | 빠지면 제출이 안 되거나 게임 루프가 끊김 | 11/19(목) 밤 |
| P1 권장 | 점수를 올리지만 없어도 게임은 완결됨 | 11/20(금) 밤, 기능 동결 |
| P2 여유 | 볼륨·완성도 확장 | 남는 시간에만 |
| 보류 | 공모전 이후 | - |

- P0가 끝나기 전에는 P1에 손대지 않는다.
- 등급을 올릴 때마다 직전 웹 빌드를 백업한다.
- 일정이 밀리면 늦게 끝내지 말고 범위를 줄인다. 컷 순서: P2 전부 -> P1 사운드·저장 -> P1 품질 검사 미니게임 -> P1 컨디션. P0는 줄이더라도 빼지 않는다.

## 심사 기준 (총 100점)

주제적합성 20 · 활용도 20 · 완성도 15 · 대중성 15 · 작품성 15 · 독창성 15.
조달 업무를 전달하는 요소(코어 루프, 나르미의 정책 설명)는 전부 P0다.

## 11/17 기획 변경 (개발자 결정)

첫 실행 검증 뒤 "재미가 없다"는 판단으로 아래를 바꿨다. 걷기 방식과 코어 루프 순서는 유지.

- 화면: 예전 모바일 타이쿤풍. 상단 정보 바(날짜·시계·피로·지갑·예산·평판), 하단 메뉴 바(업무·가방·성장·저장),
  보상 숫자 팝업·카운트업, 목표 위치 화살표(화면 밖이면 가장자리 방향 표시).
- 캐릭터: 2등신 SD로 다시 그림(임시 도트 생성 스크립트). 타일도 아늑한 톤으로 다시 그림.
- 집: 하루의 시작과 끝. 아침 집 → 출근 → 퇴근(현관) → 집 저녁 정산 → 잠 → 다음 날. 옷장에서 외형 변경, 냉장고 에너지바.
- 재미: 업무 7종 랜덤, 업무마다 검수 기준(요구 품질)과 파손 주의 → "기준을 넘는 가장 싼 업체" 판단.
  긴급(보상 1.5배)·특가·행정실 추가 부탁 이벤트. 운전 45초 → 25초 + 별(보너스 돈)·공구상자(화물 회복).
  팀 예산으로 시설 업그레이드 3종(P2 "청사 시설 확장"을 앞당김). 승진하면 일당 상승.
- 청사 맵 52x30 → 40x24로 줄여 동선 단축.

## 11/17 저녁 추가 (개발자 요청)

- 수요기관 3곳 추가(소방서·보건소·행정복지센터). 장소마다 건물 외관·간판·앞마당·담당자·주변 인물이 다르다. 학교도 같은 구조로 다시 그림. 업무 7종 → 13종.
- 나라장터 PC를 모니터 창으로: 요청 정보 카드 + 업체 카드(가격·품질 막대·기준선) + 계약 확인.
- 구내식당: 음식은 가방 아이템이 아니라 식권 발매기에서 골라 그 자리에서 먹는다(국밥·정식·카레, 하루 2끼). 식사 장면 창 → 피로·컨디션 결과.
- 참고 영상(초보자 던전 마스터)의 분위기: 크림색 말풍선 대화창, 꽃 잔디, 진한 외곽선. 에셋은 가져오지 않음.
- 조달 상식 확충과 출처 표(`docs/procurement-facts.md`). "실제로는 업체가 납품" 등 게임과 현실의 차이를 나르미가 설명.
